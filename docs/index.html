Postmortem - Bajo contraste en mensaje de bienvenida

Información general

  • ✅ Título del incidente: Bajo contraste visual en el mensaje de bienvenida
  • ✅ Fecha de detección: Durante revisión visual de la página
  • ✅ Fecha de resolución: Mismo ciclo de desarrollo
  • ✅ Responsable: Equipo de desarrollo frontend
  • ✅ Componentes involucrados: index.html / estilos CSS

Resumen ejecutivo

  • ✅ Se detectó que el mensaje "Bienvenidos a la diplomatura de UX/UI" utilizaba texto amarillo sobre fondo blanco.
  • ✅ La combinación dificultaba la lectura del contenido.
  • ✅ Se resolvió modificando el color del texto a negro para aumentar el contraste y mejorar la accesibilidad.

Impacto

  • ✅ Afectaba la legibilidad del contenido principal de la página.
  • ✅ Podía generar una mala experiencia de usuario.
  • ✅ Presentaba un problema de accesibilidad por bajo contraste.
  • ⬜ No afectó funcionalidades ni lógica de negocio.

Línea de tiempo

  • ✅ Se creó la página con texto amarillo sobre fondo blanco.
  • ✅ Durante la revisión se identificó el problema de visibilidad.
  • ✅ Se registró un issue para documentar la mejora.
  • ✅ Se implementó el cambio de color.
  • ✅ Se verificó la correcta visualización del texto.
  • ✅ Se cerró el issue.

Detección

  • ✅ Detectado mediante revisión manual de la interfaz.
  • ✅ No fue necesario monitoreo automatizado.
  • ✅ El problema era visible a simple vista.

Causa raíz

  • ✅ Selección de una combinación de colores con contraste insuficiente.
  • ✅ No se validó previamente la legibilidad del texto sobre el fondo.
  • ✅ No se consideraron criterios básicos de accesibilidad durante la implementación inicial.

Acciones tomadas

  • ✅ Se modificó el color del texto de amarillo a negro.
  • ✅ Se mantuvo el resto del diseño sin cambios.
  • ✅ Se verificó la mejora visual después de la corrección.

Qué funcionó bien

  • ✅ El problema fue detectado rápidamente.
  • ✅ La corrección fue simple y de bajo riesgo.
  • ✅ El cambio no impactó otras funcionalidades.

Qué podría mejorar

  • ⬜ Revisar contraste de colores antes de aprobar cambios visuales.
  • ⬜ Incorporar una validación básica de accesibilidad en las revisiones.
  • ⬜ Utilizar herramientas de contraste durante el diseño.

Acciones correctivas

  • ✅ Cambiar el color del texto a negro.
  • ✅ Verificar la legibilidad del contenido principal.
  • ⬜ Incorporar checklist de accesibilidad en futuras revisiones.

Acciones preventivas

  • ⬜ Evaluar contraste de colores antes de realizar merge.
  • ⬜ Revisar criterios WCAG para textos y elementos visuales.
  • ⬜ Incluir validaciones visuales en el proceso de code review.

Lecciones aprendidas

  • ✅ Un diseño visualmente atractivo puede no ser legible.
  • ✅ El contraste es un aspecto fundamental de la accesibilidad.
  • ✅ Cambios pequeños en la interfaz pueden mejorar significativamente la experiencia de usuario.

Cierre

  • ✅ Corrección implementada y validada.
  • ✅ Issue resuelto.
  • ✅ Sin impactos funcionales posteriores al cambio.
