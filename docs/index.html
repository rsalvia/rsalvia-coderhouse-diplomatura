Postmortem – Mejora de accesibilidad mediante corrección de contraste visual

Contexto

Durante el desarrollo de una página HTML de bienvenida para la Diplomatura de UX/UI, se implementó una interfaz simple compuesta por una imagen y un mensaje principal destinado a dar la bienvenida a los usuarios.

La página fue publicada utilizando GitHub Pages y posteriormente sometida a una revisión visual con el objetivo de verificar su correcta visualización y legibilidad.

Problema identificado

Durante la revisión se detectó que el mensaje principal "Bienvenidos a la diplomatura de UX/UI" se mostraba en color amarillo sobre un fondo blanco.

Si bien la implementación era funcional desde el punto de vista técnico, la combinación de colores generaba un contraste insuficiente entre el texto y el fondo, dificultando la lectura del contenido.

Impacto

  • Mayor esfuerzo cognitivo para interpretar el contenido.
  • Dificultad de lectura en determinados dispositivos o condiciones de iluminación.
  • Problemas de accesibilidad para usuarios con limitaciones visuales.
  • Percepción negativa de la calidad de la interfaz.

Análisis de causa raíz

La causa principal fue la selección inicial de una combinación de colores que no ofrecía suficiente diferencia de luminancia entre el texto y el fondo.

Durante la implementación se priorizó el aspecto visual del diseño, pero no se realizó una validación formal del contraste utilizando criterios de accesibilidad.

Fundamentación teórica

Accesibilidad y contraste visual

La accesibilidad busca garantizar que todas las personas puedan percibir, comprender y utilizar una interfaz independientemente de sus capacidades o limitaciones.

Uno de los aspectos más importantes es el contraste entre texto y fondo. Las Web Content Accessibility Guidelines, conocidas como WCAG, establecen que el contenido textual debe presentar una relación mínima de contraste para asegurar una lectura adecuada.

Cuando el contraste es insuficiente, aumenta el esfuerzo visual, disminuye la velocidad de lectura y se reduce la inclusividad de la solución.

Heurísticas de Nielsen

La corrección realizada se relaciona con principios de usabilidad como estética y diseño minimalista, reconocimiento antes que recuerdo y prevención de errores.

Una interfaz clara permite que los usuarios identifiquen rápidamente la información relevante sin realizar esfuerzos adicionales.

Diseño centrado en el usuario

El Diseño Centrado en el Usuario propone que las decisiones de diseño deben fundamentarse en las necesidades reales de las personas y no únicamente en preferencias estéticas.

Desde esta perspectiva, la accesibilidad es un atributo esencial de calidad.

Acciones realizadas

  1. Identificación y documentación del incidente mediante un Issue.
  2. Análisis del problema y definición de una solución.
  3. Modificación del color del texto de amarillo a negro.
  4. Verificación visual de la mejora obtenida.
  5. Registro de la corrección mediante Pull Request.
  6. Publicación de la versión corregida.

Resultado obtenido

  • El mensaje principal se volvió claramente legible.
  • Se incrementó significativamente el contraste visual.
  • Se mejoró la accesibilidad de la interfaz.
  • Se redujo el esfuerzo cognitivo necesario para leer el contenido.
  • La solución quedó alineada con buenas prácticas de UX y accesibilidad.

Qué funcionó bien

  • La revisión visual permitió detectar el problema tempranamente.
  • El uso de Git facilitó la trazabilidad de la corrección.
  • Issues y Pull Requests permitieron documentar el proceso.
  • La solución tuvo bajo costo y alto impacto positivo.

Oportunidades de mejora

  • Validar contraste visual antes de publicar cambios.
  • Incorporar revisiones de accesibilidad dentro del proceso de QA.
  • Utilizar herramientas automáticas de evaluación de contraste.
  • Revisar criterios WCAG durante el diseño de interfaces.

Lecciones aprendidas

Este incidente demostró que una interfaz puede ser técnicamente correcta y, sin embargo, presentar problemas de experiencia de usuario.

La accesibilidad debe considerarse desde las primeras etapas del diseño y no únicamente durante la validación final.

También se reafirmó que pequeños ajustes visuales pueden generar mejoras significativas en la percepción, comprensión y usabilidad de un producto digital.

Conclusión

La corrección del contraste visual permitió transformar una interfaz funcional en una interfaz más accesible y usable.

El proceso evidenció la importancia de combinar decisiones de diseño con criterios objetivos de accesibilidad, utilizando herramientas de control de versiones, documentación técnica y análisis retrospectivos para promover la mejora continua del producto.
